# 测试 & 验证策略

> 现状:本仓库是静态个人博客,页面验证以「真跑」为主。维护脚本已有 Node 内置测试，见下方 Stop hook 回归测试。

## 原则

- **真跑验证**:不要只读代码就收工。改完跑 `pnpm build`,再用浏览器打开受影响页面确认。
- **返回结构化文本**:用 agent-browser 读无障碍树 / DOM / 控制台,别只靠截图肉眼判断。
- **聚焦受影响路径**:博客列表、文章页、`/products`、`/photos` 各自独立,只验证你动到的那条。

## 验证某个改动是否真生效

- 构建:`pnpm build` 必须通过(含类型检查)。
- `pnpm check` 末尾的 `oxfmt` 会原地改写源文件，必须等它结束再运行 `pnpm build`，避免构建读取到格式化写入中的文件而误报语法错误。
- 起服务:`pnpm dev`,记下实际端口(可能 4321/4322…)。
- 用浏览器看页面:
  - 首页 `/` — 简介行 + 按年份归档的文章列表 + 版权信息之后的全宽草甸。
  - 文章页 `/blogs/<slug>` — 正文、代码块复制/折叠、TOC、云图片加载。
  - `/products` — 左栏简介 + 瀑布流 + 右下角三主题切换。
  - `/photos` — 横向照片流 + 底部拨盘时间轴(滚动/拖动联动)。
- 交互逻辑(如摄影页拨盘联动、webgl-viewer 缩放)无法靠读代码确认,必须真操作一遍。

## 什么时候补自动化测试

- 引入纯逻辑工具(如 `src/lib/` 下新算法、cloud-image Key 解析规则)→ 加单元测试。
- 引入测试框架时:Web E2E 用 Playwright CLI / agent-browser(读无障碍树,确定性、可进 CI),并把测试命令接进 `pnpm check` 或 pre-commit 才算真强制。

## 完成闸门

- 收尾跑 `node scripts/check-docs.mjs`(0 ❌)+ `pnpm check`。
- 已装 Stop hook(见 [.claude/settings.json](../.claude/settings.json) 和 [.codex/hooks.json](../.codex/hooks.json)),文档检查会在收尾自动跑 `check-docs --hook`。成功时 stdout 必须是 JSON；有 ❌ 时诊断只写 stderr，以 `exit 2` 拦截收尾。

## Stop hook 回归测试

- `pnpm test:hooks` 使用 Node 内置 `node:test`，并已接入 `pnpm check`。
- 在临时目录中真实运行检查器，覆盖成功 JSON、普通 CLI 文本报告、缺文件头、失效链接、非阻断漂移警告和严格模式；同时校验两个 Agent 的 Stop 配置仍调用被测入口。
- 测试先解析完整 stdout，防止在 JSON 前后混入日志；失败场景验证退出码 `2` 与 stderr 的修复说明，防止为了消除报错而失去检查能力。
- 本次回归作用于命令行 hook 协议，没有受影响的网页；用实际子进程输出与退出码验收。

## 首页草甸回归

- `pnpm test:meadow` 已接入 `pnpm check`，覆盖共享排布与预览一致、90% 株数、种子稳定、空尺寸与首页独有的挂载边界（ADR-0006）。
- 浏览器检查桌面和窄屏底边、微风变化、屏外暂停、减少动态效果静止；通过站内链接进入文章再回首页，确认旧元素清理且新元素恢复动画。
- WebGL 不可用时检查静态位图组合仍显示；生产构建的其他路由不能含草甸元素或草甸脚本。

## 小猫尾巴实验

- `pnpm test:meadow` 同时执行猫尾巴纯动作回归，覆盖连接固定、零幅度、休息段、循环连续、位移范围和网格不翻折。
- 原花草 demo 的 `#cat-board` 是独立画布；检查猫与花草的暂停和幅度互不影响、只看尾巴、网格、窄屏、屏外和后台暂停、减少动态效果与静态回退。
- 用户选择自行打开原 demo 时不自动夺回其浏览器任务空间；记录尚未完成的实屏验证，不能用纯函数或 HTTP 检查声称已完成视觉验收。

## 小猫跑跳实验

- `pnpm test:meadow` 覆盖八帧跑姿、跳跃图集与过渡图集、蓄力/腾空/缓冲、自动循环休息占比、单次动作落点与向内折返，以及真实图集 alpha/留白/窄屏裁切。
- 在 `#cat-board` 看自动演示、跑一段、跳一下、坐下休息、暂停、慢放与尾巴实验；检查离开视口和后台停表，单次动作完成不传送回起点，减少动态效果默认静止，猫和花草控件独立。
- 坐站与跑跳前后已补过渡，但仍有生成细节差异；需实屏判断起身/坐下、转身、跑姿循环、落地接触、影子与毛发跳变，不能由静态资源测试宣称动画已足够自然。
- 骨架观察：开关辅助线、只看骨架、拖动进度、暂停后续播；检查当前姿势序号、左右折返和跳跃中的对齐，以及尾巴实验“只看尾巴”的范围。标注是人工示意，不是驱动图片的骨骼。
- 自动回归覆盖可见标记位于真实图集主体、镜像/离地投影、原始标注不变、坐姿尾巴节点与实际网格同动；实屏检查不能由这些数据约束替代。
- 过渡回归执行 ADR-0008：任意时刻请求动作都等待安全节点，接续时位置、朝向、原画、观察距离及尾巴幅度不跳变；飞行必须落地恢复；起跑与收步速度连续，自动回场前缀只播放一次。真实 alpha 检查包含四张新过渡图集。
- 实屏需补看：跑动时点休息、腾空时点跑步、连续点击后以最后请求为准、排队提示、进度拖动取消请求、坐起和折返转身、尾巴实验进出时缩放及摆动是否接上。

## 蝴蝶振翅与飞行

- `pnpm test:meadow` 包含蝴蝶八姿势循环、飞行首尾连续、观察模式不改相位、放大过渡与中途反向；真实图集 alpha、透明留白、注册点和宽窄屏边界一并检查。
- 原页 `#butterfly-board` 实看自在飞行与原地振翅切换、暂停、0.5× / 0.25× 慢放、轨迹开关、身体稳定和翼尖不串帧；快速切模式不突然换位置，猫与草控制互不影响。
- 检查手机无裁切，后台/屏外暂停，减少动态效果默认静止、主动播放可运行，脚本/Canvas 失败显示静态原画。用户自行打开期间不重新接管浏览器，程序检查不能算实屏验收。

## 草丛追蝶

- `pnpm test:meadow` 的 `chase.test.mjs` 执行 ADR-0009：落花后伏低等待 1–2 秒、猫接近才逃离、跑动连续接扑跳、花头落点和风动投影、跨阶段/循环位置与缩放后的阶段保持。
- 解码真实新图集检查 alpha 与留白，240/280/335/375/640/1327px 检查整个循环的猫/蝶轮廓范围；原 PNG alpha 交叠检查前草实际遮挡部分猫身。
- 实屏仍需看 `#chase-scene` 的探头可见性、花头脚部贴合、毛发/体型跨图集变化、连续跑扑与转身；操作暂停、慢放、拖动、从头播放，检查手机、屏外/后台停表、减少动态效果与 WebGL 丢失/恢复。用户自行查看期间不另开浏览器任务，HTTP 和纯函数通过不等于实屏已验收。
- 贴地回归检查草根地面与真实接触帧脚底，允许脚尖被底边遮住但不允许头身裁切；软阴影高度固定在地面，跳起后变淡。实屏需分别看静止、跑步落脚和跳后落地，不能只用“在画布范围内”推断猫没有悬空。

## 首页双蝴蝶

- `home-butterflies.test.mjs` 接入 `pnpm test:meadow`：四张图集的真实颜色/透明度/留白，两个不同周期及候选花株，花头/网格贴合，起落/周期位置与倾斜连续，240–1920px 真实轮廓范围。ADR-0010 约束首页客户端不加载猫/demo 模块；ADR-0006 继续约束首页独有挂载。
- 构建产物确认两只静态蝴蝶、四张压缩 WebP、无猫图片与脚本，文章/作品/摄影页没有草甸挂载。原 demo 共享渲染器新增 wind 模块后检查白名单资源依赖仍可用。
- 实屏检查首页底部两色蝴蝶同时可见、振翅节奏错开、落花随风、起飞衔接；确认屏外/后台停表、减少动态静止、ClientRouter 往返与静态回退。用户继续自行打开，未经实屏操作不能宣称视觉验收完成。
